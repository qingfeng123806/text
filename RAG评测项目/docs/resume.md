# 简历材料：Agent 行为审计与回归评测系统

> 所有数字均来自 `python run.py stats --run-id demo-latest` 的实际输出，可现场复核。
> 项目性质为**个人项目**，不要包装成公司/团队项目。

---

## 一、推荐版（4 条，适合简历主项目位）

**Agent 行为审计与回归评测系统**　个人项目
`Python 3（纯标准库 / 零依赖）· 哈希链审计 · 评测框架 · http.server · 原生 JavaScript`

- 以退款客服 Agent 为载体，独立实现「审计—评测—回归」三层质量设施：规则内核 4 条业务约束，
  评测层 20 条用例 + 7 条全局不变式，单次运行执行 223 个校验点（83 用例断言 + 140 不变式检查）。
- 设计「用例断言 + 全局不变式」两级判定，不变式对所有用例无条件生效，用于捕获"资金已被账本拦住、
  但 Agent 仍发起违规调用"这类结果正确、行为违规的问题；据此定位某缺陷版本的 5 次幂等违规。
- 实现基线对比回归引擎，把结果划分为新增回归 / 已修复 / 稳定通过 / 存量失败四类并归因到业务规则；
  对 5 个植入缺陷的 Agent 版本识别出 24 条回归，全部落到 R1–R4 具体规则，有回归时进程返回 1，
  可直接作为 CI 门禁。
- 实现 SHA-256 前向哈希链审计日志（6 条流 / 552 事件），可检出篡改、删除、插入三类攻击并定位到
  具体条数；修复"同一运行 ID 重跑导致审计事件静默累积"缺陷，改为旧链归档，保证「一条链 = 一次运行」。

## 二、加强版（6 条，适合作为唯一主项目、版面充足时）

在上面 4 条之后追加：

- 以虚拟时钟替代真实 sleep，使 20 用例 × 6 个版本的跑批耗时降到 0.2s，且耗时字段完全可复现，
  避免时间抖动污染回归对比结果。
- 基于 `http.server` + 原生 JS 自建可视化控制台（轨迹时间线回放、回归 Diff、审计链校验），
  支持 `file://` 直开时的端口探测与跨域访问，并处理请求超时、切页竞态与骨架屏加载态。

## 七、红线：这些不要写

- **不要写"准确率 / 召回率 / 精度 X%"**。本项目判定是确定性的（通过/不通过、违规/不违规），
  没有统计意义上的准确率。写上去被追问一句就露底。
- **不要把"6 个 Agent 版本"改写成"6 类业务场景"**。业务规则只有 4 条，版本是 1 个基线 + 5 个缺陷变体。
- **不要写"日活 / QPS / 用户量"**。没有线上流量，是本地评测系统。
- **不要写"独立设计分布式架构"** 这类与你实际做的不符的词。它就是个单机评测 + 审计系统，
  这一点本身不丢人，说清楚反而加分。

## 八、面试追问预案

**Q1：不变式和用例断言有什么区别？为什么不都写成用例？**
用例断言回答"这个场景应该怎样"，只对写了的场景生效；不变式回答"任何时候都不许这样"，
对所有用例无条件生效。新增用例时不用记得补"防重复打款"——它本来就在。这是评测层能兜底的原因。

**Q2：哈希链怎么防篡改？改一条会怎样？**
`rec[i].hash = SHA256(rec[i-1].hash ‖ canonical(rec[i]))`。改任意一条内容，它自己的哈希就对不上；
删除或插入会让后续记录的前向哈希断裂，校验能定位到断在第几条。实测三类攻击（篡改/删除/插入）
全部检出并定位。

**Q3：为什么重跑要归档而不是续写？**
审计的语义是"一条链 = 一次运行的全部证据"。续写会让两次运行的事件混在一条链里，
链长不再对应任何一次真实运行；覆盖又会丢证据。所以选择归档到 `audit/archive/`，
两条链各自完整可校验。这个问题是统计事件数时发现每流 184 条、而实际一次只该 92 条才暴露的。

**Q4：为什么自己做时钟？**
超时类用例如果真 sleep，跑批慢且耗时抖动，回归对比时会误判。用虚拟时钟精确累加耗时，
20 用例 × 6 版本约 0.2s，且 `duration_ms` 完全可复现。

**Q5：为什么不用 pytest / FastAPI？**
目标场景是"在一台没有外网的机器上也能跑"，装依赖本身就是风险，所以只用标准库；
断言引擎自研是为了让断言类型可扩展、且未知断言类型显式报错而不是被静默忽略。

**Q6：这个项目里你抓到的最有价值的 bug？**
评测跑出来基线自己挂了一条用例：超时后后台已结算的路径落了成功账，却没同步订单状态，
账实不一致。修法是把"落账 + 更新状态"合并成单一入口，两条路径都只走它。
——这个 bug 不是我读代码看出来的，是评测层抓出来的，正好说明这套设施的价值。

**Q7：为什么不测"准确率"？**
Agent 的行为判定是确定性的：这条用例要么符合预期要么不符合，违规更是硬性事实。
能报的是通过率（通过用例数/用例总数）、违规次数、回归条数，这些都可核对。
